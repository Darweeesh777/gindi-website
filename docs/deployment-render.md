# Server deployment on Render

> **Status:** not in use. The free preview runs on Cloudflare Pages instead;
> see [deployment-cloudflare.md](deployment-cloudflare.md). Render asked for
> a payment card (a $1 verification) to deploy the Blueprint, even on the
> free plan. This setup stays ready for when a server host is wanted, e.g.
> for `/admin/` or to store enquiries.

This setup runs the site as a Django server on Render's free plan, from the
private GitHub repository `gindi-website`, branch `main`, and redeploys
automatically on every push to `main`.

Everything Render needs is in the repository:

| File | Purpose |
|---|---|
| `render.yaml` | Render Blueprint: one free Python web service |
| `build.sh` | Build: install packages, `collectstatic`, `migrate`, optional admin account |
| `gunicorn.conf.py` | Gunicorn (WSGI server) settings |
| `.python-version` | Python 3.13 (Render uses the latest 3.13.x) |
| `requirements.txt` | Pinned Python packages |
| `config/settings/production.py` | Production settings, all from environment variables |

## Exact commands

| | Command |
|---|---|
| Build command | `bash build.sh` |
| Start command | `gunicorn -c gunicorn.conf.py config.wsgi:application` |

`build.sh` runs, in order:

```bash
pip install --upgrade pip
pip install -r requirements.txt
python manage.py collectstatic --noinput
python manage.py migrate --noinput
# only if DJANGO_SUPERUSER_USERNAME and DJANGO_SUPERUSER_PASSWORD are set:
python manage.py createsuperuser --noinput
```

## Environment variables

Set by `render.yaml` (Render > service > **Environment** shows them):

| Variable | Value | Why |
|---|---|---|
| `DJANGO_SETTINGS_MODULE` | `config.settings.production` | `DEBUG=False`, HTTPS, WhiteNoise, logging |
| `DJANGO_SECRET_KEY` | generated by Render | Random 256-bit value; never in the repository |
| `DATABASE_URL` | `sqlite:///db.sqlite3` | See *Database* below |
| `WEB_CONCURRENCY` | `2` | Gunicorn worker processes |
| `SITE_NOINDEX` | `true` | Keep search engines out (preview) |
| `DJANGO_SECURE_HSTS_SECONDS` | `0` | HSTS off on the preview |

Set automatically by Render: `RENDER_EXTERNAL_HOSTNAME` (the
`….onrender.com` name). The settings add it to `ALLOWED_HOSTS` and
`CSRF_TRUSTED_ORIGINS`, so no host needs to be typed in. `PORT` is also
provided by Render and read by `gunicorn.conf.py`.

Optional, add in the **Environment** tab when ready. Never commit them, and
never paste them into a chat:

| Variable | Effect when set |
|---|---|
| `ENQUIRY_FORM_ACTION` | Enquiry form posts there (e.g. a form service). Empty: the form says it is not connected and cannot be sent |
| `WHATSAPP_NUMBER` | Shows "Chat with Us on WhatsApp" (digits, international format). Empty: no button |
| `FREE_TOOL_WIRE_SCRIPT_URL`, `…_TILES_…`, `…_BRICKS_…`, `…_CEMENT_…` | Loads that tool's agent. Empty: "Coming soon" |
| `DJANGO_SUPERUSER_USERNAME`, `DJANGO_SUPERUSER_PASSWORD`, `DJANGO_SUPERUSER_EMAIL` | `build.sh` creates an `/admin/` account on the next deploy |
| `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS` | Extra hostnames (only for a custom domain later) |
| `DJANGO_LOG_LEVEL` | Django log level (default `INFO`) |

Saving a changed variable redeploys the service.

## Database

**What the site actually needs:** no website page makes a database query.
The content lives in Python files (`apps/core/*.py`), and there are no models,
forms or uploads. Only Django's built-in **admin**, **login sessions** and
**permissions** use the database.

**Chosen for the preview: SQLite, created fresh by each build.**
`build.sh` runs `migrate`, so `/admin/` works. Render's free web services have
an **ephemeral filesystem**: anything written while the site runs is lost on
every redeploy, restart and spin-down. For this site, that means:

- the pages are unaffected;
- an admin account exists only if the `DJANGO_SUPERUSER_*` variables are set,
  and it is re-created at each build;
- admin logins are signed out whenever the instance restarts or sleeps;
- anything changed through the admin is lost (there is currently nothing to
  manage there).

Nothing was removed: `/admin/` still exists and works.

**Not chosen: Render's free PostgreSQL.** It expires **30 days** after
creation and is deleted **14 days** later unless upgraded. It is limited to
1 GB, has no backups, and only one is allowed per workspace. It would add an
expiry date without storing anything the site needs. When real data arrives
(e.g. stored enquiries), switch to a persistent database by setting
`DATABASE_URL=postgresql://…`. `psycopg` is already installed for this.

## Free plan limits (Render, checked 2026-10-15)

- The service **sleeps after 15 minutes without traffic**. The next visit
  waits about **one minute** while it wakes, and Render shows a loading page.
- There are 750 free instance hours per workspace per month (a sleeping
  service uses none). If they run out, free services are suspended until the
  next month.
- There is a single instance, no persistent disk and no shell. Render may
  restart free services at any time.
- Bandwidth and build minutes count against the free monthly allowance.
  Without a payment method on file, the service is suspended rather than billed.

## Search engines and access

- Every response, including images, files and error pages, carries
  `X-Robots-Tag: noindex, nofollow`. Every page has
  `<meta name="robots" content="noindex, nofollow">`.
- `/robots.txt` deliberately **allows** crawling. A crawler blocked by
  robots.txt never sees the noindex rule, and the URL could then still be
  listed without content.
- **The preview URL is still public.** Anyone who has or guesses the link can
  open it. noindex only keeps it out of search results. Render's free plan
  has no password protection. Adding one (e.g. HTTP basic auth in Django, or
  Cloudflare Access in front of a custom domain) is a separate step.

## HTTPS and security

Render ends HTTPS at its proxy and forwards requests with
`X-Forwarded-Proto`. `SECURE_PROXY_SSL_HEADER` trusts that header, and
`SECURE_SSL_REDIRECT` sends plain HTTP to HTTPS. Cookies are `Secure`, and
the security headers are on: `X-Frame-Options: DENY`, `nosniff`,
`Referrer-Policy` and `Cross-Origin-Opener-Policy`.

HSTS stays off on the preview. Enable it on the real domain once HTTPS is
confirmed (`DJANGO_SECURE_HSTS_SECONDS=3600`, later `31536000`).

`manage.py check --deploy` reports two expected warnings on the preview:

- W004, HSTS off (as above);
- W009, secret key shorter than 50 characters. Render's generated value is
  44 base64 characters (256 random bits), which is strong. Django's check
  measures length, not randomness.

## Static files

WhiteNoise serves the output of `collectstatic` directly from Gunicorn:

- file names carry a content hash (`base.fd70ad4f4365.css`);
- files are pre-compressed with Brotli and gzip;
- browsers cache them for a year.

Only the images the site uses are in the repository
(`static/images/site/`, `static/images/brand/`). The large source masters at
the root of `static/images/` stay on the local machine (git-ignored).

## Logs and errors

Render > service > **Logs** shows Gunicorn's access log, 404 warnings and the
full traceback of any server error (500). Visitors see branded error pages:
`templates/core/404.html` (English or Arabic) and `templates/500.html`
(self-contained, bilingual). No external error tracker is connected.

## Publishing updates

```powershell
git add -A
git commit -m "Describe the change"
git push
```

Render rebuilds and redeploys `main` automatically, usually within a few
minutes (Render > service > **Events** shows progress). If a build fails, the
previous version stays live.
